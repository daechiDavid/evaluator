<서비스 개요와 기본 운영 원칙>

이 서비스는 초등학교 교사가 교과 평가 문장, 행동특성 및 종합의견, 창의적 체험활동 자율활동 문장을 생성하는 웹 애플리케이션이다. Windows 전용 로컬 프로그램으로 만들지 않고, 최신 데스크톱 브라우저에서 사용할 수 있는 반응형 웹앱으로 개발하여 Vercel에 배포한다.

소스 코드는 사용자가 이미 만들어 둔 GitHub의 `evaluator` 저장소에서 관리하고 같은 저장소를 Vercel 프로젝트의 Git 배포 소스로 연결한다. GitHub 인증·저장소 확인·Pull Request 작업은 GitHub CLI로, Vercel 로그인·프로젝트 연결·환경 변수·Git 연결·배포 확인은 Vercel CLI로 수행한다. CLI가 시작한 브라우저 인증·GitHub App 권한 동의는 허용하지만 GitHub 또는 Vercel 대시보드에서 저장소나 배포를 별도로 만들고 수동 연결하는 절차를 기본 흐름으로 사용하지 않는다.

정상 배포 흐름은 기능 브랜치 push와 Pull Request가 Vercel Preview를 자동 생성하고, 검증된 Pull Request를 Production Branch인 `main`에 병합하면 Vercel Production이 자동 배포되는 방식이다. `vercel deploy`와 `vercel deploy --prod` 직접 배포는 일상적인 릴리스 경로로 사용하지 않고 Git 연동 장애의 진단·복구처럼 명시적으로 승인된 예외에만 사용한다. 기존 `evaluator` 원격 저장소에 커밋이 있으면 강제 push나 이력 덮어쓰기를 하지 않고 먼저 fetch하여 안전하게 이력을 합친다. 저장소는 이미 존재하므로 `gh repo create`로 다시 만들지 않는다.

학생 명단을 등록하거나 업로드하는 기능은 제공하지 않는다. 이름, 학번, 반, 연락처와 같은 학생 식별 정보도 입력받지 않는다. 생성 대상은 화면에서 ‘학생 1’, ‘학생 2’처럼 순번으로만 구분하며, 교사는 내려받은 결과를 자신의 학생 명단과 직접 대조하여 사용한다.

문장 생성, 문서 내용 추출과 의미 기반 검수에는 Google Gemini 3.5 Flash Lite만 사용한다. 브라우저가 Google Gemini API를 직접 호출하지 않으며, 모든 모델 요청은 Vercel의 서버 측 함수에서 수행한다. Gemini API 키는 최대 세 개까지 Vercel 환경 변수에만 저장하고 화면에서 입력받지 않는다. 서버는 사용 가능한 키를 정해진 순서로 선택하며 어떤 키도 클라이언트에 전달하지 않는다.

브라우저 개발자 도구의 Network 탭에서 프론트엔드가 호출한 주소 자체를 완전히 숨기는 것은 불가능하다. 따라서 브라우저에는 같은 도메인의 내부 요청만 보이게 하고, Google API 주소, API 키, 모델 제공자 전용 요청 구조는 노출하지 않는다. Google API 호출 코드와 SDK는 서버 전용 모듈에 두고 클라이언트 번들에 포함하지 않는다.

사용자에게 받는 길이 설정은 기능 1, 2, 3 모두 ‘한 문장당 목표 글자 수’로 통일한다. 글자 수는 띄어쓰기, 줄바꿈과 문장부호를 모두 제외하고 계산한다. 허용 범위는 목표 글자 수의 마이너스 5자부터 플러스 5자까지로 고정하며 사용자가 변경할 수 없다. Gemini에게 범위 안에 맞게 작성하도록 요청하고, 서버가 생성 후 실제 글자 수를 검사한다. 허용 범위를 벗어난 문장은 해당 문장만 자동으로 다시 생성한다.

교사나 학교별 문장 작성 원칙, 명사형 종결 규칙, 금지 표현과 권장 표현은 공통 템플릿으로 관리하여 모든 기능에서 반복 사용한다. 기본 템플릿은 서비스에 포함한다. 사용자가 문장 작성 원칙을 보충해야 할 때는 별도 설정 탭이 아니라 각 기능 화면의 접이식 ‘공통 작성 옵션’에서 편집하며, 변경 내용은 모든 기능에 공통 적용하고 해당 브라우저에 저장한다.

생성 결과에는 최종 평가 문장 본문만 포함한다. 문장 앞에 번호, 순서, 불릿, 별표, 해시, 대시, 제목, 항목명, 설명문, 코드 블록과 같은 마크다운 표식이나 불필요한 기호를 추가하지 않는다. 정상적인 한국어 문장 표현에 필요한 문장부호만 허용하고, 모든 개별 문장은 마침표로 끝나야 한다. 서버는 생성 후 형식을 검사하고 규칙을 어긴 해당 문장만 재생성한다.

영어 교과를 포함한 모든 교과의 최종 평가 문장은 한국어로만 작성한다. 영어 알파벳, 영어 단어, 영문 예시와 외국어 표현을 최종 문장에 포함하지 않는다. 예를 들어 영어 교과에서도 ‘일상생활에 관한 대화를 듣고 중심 내용을 이해함.’과 같이 한국어로 작성한다. 서버는 영어 알파벳 포함 여부를 검사하고, 포함되었으면 해당 문장만 재생성한다.

최종 문장의 숫자 표현도 가능한 범위에서 아라비아 숫자 대신 한글로 작성한다. 예를 들어 ‘3회’보다 ‘세 차례’, ‘2개’보다 ‘두 개’를 우선한다. 공식 활동명, 고유명사 또는 의미 전달에 반드시 필요한 경우에만 숫자 사용을 허용한다.

<화면 구성과 설정 탭 제거>

주요 내비게이션은 기능 1, 기능 2, 기능 3 화면으로만 구성하고 별도의 설정 탭은 만들지 않는다. Gemini API 키, 모델명, 외부 API 주소와 시스템 프롬프트는 사용자가 입력하거나 변경하는 항목이 아니므로 화면에 표시하지 않는다. 앱은 API 키 입력을 요구하거나 클라이언트에 저장하는 대체 흐름도 제공하지 않는다.

사용자가 실제로 조정할 필요가 있는 학생 수, 목표 글자 수, 키워드, 활동 주제와 공통 작성 옵션은 해당 기능 화면 안에 배치한다. 기능 1의 교과 평가 문장은 항상 ‘상’ 성취 중심으로 생성하므로 상·중·하를 선택하거나 변경하는 입력은 제공하지 않는다. 공통 작성 옵션은 기본적으로 접어 두어 핵심 생성 흐름을 방해하지 않게 하고, 변경 시 모든 기능에서 사용하는 localStorage 데이터에 반영한다. 기본값 복원도 이 영역에서 제공한다.

브라우저에 저장된 현재 작업과 생성 결과를 관리하는 기능은 독립된 설정 탭 대신 헤더의 ‘브라우저 데이터 관리’ 메뉴로 제공한다. 이 메뉴에는 현재 작업 삭제, 전체 저장 데이터 삭제와 필요 시 결과 내보내기만 둔다. 삭제 범위와 복구 불가능 여부를 확인받되 API, 모델과 배포 환경 설정은 포함하지 않는다.

서버에 유효한 GEMINI_API_KEY_1 또는 GEMINI_MODEL이 없으면 문장 생성 기능을 비활성화하고 ‘서비스 설정 오류로 생성 기능을 사용할 수 없음’이라는 일반적인 안내만 보여준다. 선택 키인 GEMINI_API_KEY_2와 GEMINI_API_KEY_3이 없으면 설정된 키만 숫자 순서로 사용한다. 사용자에게 API 키 입력을 요청하여 우회하지 않으며, 구체적인 환경 변수 이름과 외부 API 오류는 운영 로그의 비밀 정보가 없는 진단 코드로만 확인한다.

<작업 데이터와 개인정보>

서버 데이터베이스에 학생 명단, 업로드 문서, 생성 입력과 생성 결과를 영구 저장하지 않는다. 작업 중 서버가 받은 자료는 해당 요청 처리에만 사용하고 응답 완료 후 애플리케이션 저장소에 남기지 않는다. Vercel과 Google의 실제 데이터 처리 및 보존 정책은 배포 전에 확인하여 개인정보 처리 안내에 반영한다.

화면 새로고침이나 브라우저 종료에 대비한 입력 초안, 생성 결과, 검수·확정 상태와 사용자 템플릿은 브라우저의 localStorage에 JSON 형식으로 자동 저장한다. 공용 PC에서 사용할 수 있으므로 사용자가 현재 작업 또는 모든 브라우저 저장 데이터를 직접 삭제할 수 있게 하고, 저장 데이터가 현재 브라우저와 기기에 평문으로 남는다는 사실을 명확히 안내한다. 민감한 학생 식별 정보는 입력하지 않도록 각 입력 화면에 안내 문구를 표시한다.

<로컬 스토리지 저장 가능성 검토>

현재 구조에서 생성 문장 결과를 localStorage에 저장하는 기능은 구현 가능하다. 생성 결과는 학생 이름이나 파일이 아닌 순번 기반의 짧은 텍스트와 선택값으로 구성되므로, 서버 데이터베이스 없이 브라우저를 닫았다가 다시 열어도 작업을 복구하려는 목적에 적합하다. 생성 완료, 직접 수정, 재생성, 최종 확정 시점마다 현재 상태를 직렬화하여 저장하고 앱을 다시 열 때 복원한다.

localStorage는 같은 출처의 브라우저에서만 접근할 수 있고 서버 렌더링 단계에는 존재하지 않으므로, 저장과 복원 코드는 클라이언트 컴포넌트에서 브라우저가 로드된 뒤에만 실행한다. 서버에서 받은 초기 화면과 localStorage 복원 상태가 달라 생기는 화면 불일치를 막기 위해 최초 마운트 이후 복원하고, 복원 완료 전에는 저장된 작업을 덮어쓰지 않는다.

저장 항목은 기능별 입력값, 학생 수, 학생 순번별 키워드, 활동 주제 배정, 생성 문장, 검수 결과, 최종 확정 상태, 최근 수정 시각과 데이터 스키마 버전으로 제한한다. 기능 1에는 사용자 수준 선택값이 존재하지 않으므로 수준 필드를 저장하지 않는다. 키는 서비스 전용 접두사와 기능·작업 식별자를 조합하여 충돌을 막는다. 저장 데이터에 API 키, 업로드 파일의 원본·Base64 데이터, Gemini 요청용 시스템 프롬프트, 원본 모델 응답과 학생 식별 정보는 포함하지 않는다.

localStorage는 동기식이며 브라우저별 저장 용량이 제한되고, 사용자가 사이트 데이터나 브라우저 기록을 삭제하면 함께 사라진다. 암호화 저장소도 아니므로 공용 PC에서는 다른 사용자가 같은 브라우저 프로필로 결과를 볼 수 있다. 앱은 이 한계를 저장 안내에 표시하고, 자동 저장 실패와 용량 초과를 감지하여 사용자에게 XLSX 다운로드 또는 불필요한 이력 삭제를 안내한다.

한 번에 모든 이력을 무제한 저장하지 않는다. 현재 작업과 최근 확정 결과를 중심으로 보관하고, 앱이 정한 최대 보관 개수나 예상 저장 용량을 넘으면 오래된 미확정 이력부터 삭제하기 전에 사용자에게 알린다. 별도의 보관 개수 설정 UI는 제공하지 않는다. 저장 데이터에는 스키마 버전을 포함하여 앱 업데이트 후 마이그레이션하거나 호환되지 않는 데이터만 안전하게 초기화할 수 있게 한다. 생성 결과의 규모가 localStorage에 적합한 범위를 지속적으로 넘게 되면 이후 IndexedDB로 교체하되 서버 API와 화면 데이터 구조는 유지한다.

기능별 화면에는 해당 기능의 현재 입력과 결과만 지우는 초기화 버튼을 둔다. 초기화 전에 영향을 받는 항목을 보여주고 확인을 받는다. 전체 브라우저 저장 데이터 삭제는 헤더의 ‘브라우저 데이터 관리’ 메뉴에서 실행하며, 공통 작성 옵션과 생성 이력까지 삭제된다는 사실을 재확인한 뒤 처리한다.

<기능1> 평가계획서 내용을 기반으로 교과 평가 문장을 출력하는 기능

교사가 학년 평가계획서 또는 과목별 평가계획서를 PDF, 이미지, DOCX, PPTX, XLSX 파일로 업로드한다. 학년 전체 평가계획서 하나를 업로드하거나 교과별 여러 파일을 한 번에 업로드할 수 있게 한다. HWP 또는 HWPX 문서는 직접 처리하지 않고 PDF로 변환하여 업로드하도록 안내한다.

업로드 파일은 브라우저에서 Gemini로 직접 전송하지 않는다. Vercel 서버가 파일 형식과 용량을 검증하고, PDF와 이미지는 Gemini의 문서·이미지 이해 기능으로 처리한다. DOCX, PPTX와 XLSX는 서버에서 텍스트와 표 구조를 안전하게 추출한 뒤 Gemini에 전달한다. Gemini는 교과 또는 과목명, 학년, 학기, 평가 영역, 성취기준, 평가요소와 문서에 있는 경우 ‘상’에 해당하는 최고 단계 평가 수준을 구조화된 형식으로 추출한다. 중·하 평가 수준은 문장 생성 입력으로 사용하지 않는다.

여러 문서에서 같은 교과, 성취기준 또는 평가요소가 반복되면 문자열 비교와 Gemini의 의미 판정을 이용해 중복을 병합한다. 자동으로 판단하기 어려운 충돌 항목만 문장 생성에서 제외하고, 나머지 항목은 계속 처리한다. 제외된 항목은 오류 목록으로 보여주며 교사가 수정한 뒤 해당 항목만 다시 처리할 수 있게 한다. 정상 추출 결과도 생성 전에 교사가 교과명과 내용을 검토하고 수정할 수 있게 한다.

사용자는 생성에 필요한 학생 수를 양의 정수로 입력한다. 프로그램은 입력한 수만큼 ‘학생 1’부터 순서대로 행을 만들고, 평가계획서에서 확정한 모든 교과에 대해 동일한 수의 결과를 생성한다. 학생 명단 파일 업로드, 학생 이름 입력과 명단 저장 기능은 제공하지 않는다.

평가계획서에서 확정한 모든 교과를 하나의 배치 작업으로 생성할 수 있다. 사용자는 교과별 학년, 학기, 평가 영역, 평가요소, 한 문장당 목표 글자 수와 학생 수를 확인한 뒤 전체 교과 생성을 시작한다. 각 교과에서 평가요소당 한 문장을 생성한다. 예를 들어 국어 교과에 평가요소가 세 개이면 요소별 한 문장씩 총 세 문장을 연결한 하나의 문단을 학생 수만큼 생성한다. 모든 문장은 명사형 종결 어미를 사용한다.

기능 1은 모든 교과·학생 순번·평가요소에 대해 예외 없이 ‘상’ 성취 중심의 평가 문장을 생성한다. 사용자에게 상·중·하 중 하나를 묻는 선택 UI, 수준 매트릭스, 일괄 수준 설정과 개별 수준 변경 기능을 제공하지 않는다. 클라이언트 요청과 localStorage 스키마에도 기능 1 수준 필드를 두지 않으며, 서버가 고정된 ‘상’ 기준을 생성 프롬프트에 적용한다. 평가 점수, 점수 구간, 별도의 평가 근거나 교사 메모도 입력받지 않는다.

평가계획서에 ‘상’ 평가 수준 설명이 있으면 성취기준·평가요소와 함께 근거로 사용하고, 별도 수준 설명이 없으면 성취기준과 평가요소 안에서 높은 성취가 드러나는 긍정적 표현을 작성한다. ‘상’ 중심은 입력에 없는 구체적인 활동·수치·수상·역할 또는 성취 사실을 만들어도 된다는 뜻이 아니다. 모든 학생 순번에 같은 기준을 적용하되 학생마다 표현, 문장 구조와 강조점이 실질적으로 다른 결과를 생성한다.

생성 결과의 조회, 확정, 재생성과 내보내기는 교과별로 구분한다. 사용자가 교과 하나를 선택하면 해당 교과의 ‘학생 1’부터 마지막 순번까지의 최종 문단만 보여준다. 다른 교과 결과를 섞지 않고 해당 교과 결과만 복사하거나 XLSX로 내려받을 수 있게 한다.

<기능2> 핵심 키워드로 행동특성 및 종합의견을 생성하는 기능

날짜별 관찰 기록 누적, 관찰 내용 입력, 관찰 기록 XLSX 업로드와 관찰 기록 자동 분류 기능은 제공하지 않는다. 기능 2는 핵심 키워드를 선택하거나 직접 입력한 뒤 행동특성 및 종합의견을 생성하는 방식으로 단순화한다.

화면에는 학교생활 전반, 교우 관계, 학업 태도, 장점 및 발전 가능성과 관련된 핵심 키워드를 충분히 나열한다. 예시는 책임감, 성실성, 규칙 준수, 정리 정돈, 배려, 협력, 경청, 의사소통, 리더십, 공동체 의식, 자기 주도성, 집중력, 탐구심, 문제 해결력, 창의성, 발표력, 끈기, 자신감과 발전 가능성 등이다. 기본 키워드 목록과 분류는 개발자가 코드에서 관리하는 별도 데이터 모듈로 분리하여 배포 시 추가하거나 수정할 수 있게 하며, 이를 위한 사용자 설정 화면은 만들지 않는다.

사용자는 생성할 학생 수를 입력하고, 각 학생 순번 카드에서 키워드를 여러 개 복수 선택한다. 목록에 없는 특징은 직접 입력한 뒤 사용자 정의 키워드 칩으로 추가할 수 있다. 선택한 키워드는 다시 누르거나 삭제 버튼을 눌러 해제할 수 있고, 학생 순번 사이에 선택 내용을 복사하는 기능도 제공한다. 최소 한 개 이상의 키워드를 선택하거나 직접 입력해야 문장을 생성할 수 있다.

사용자는 한 문장당 목표 글자 수를 입력한다. 행동특성 및 종합의견은 선택한 키워드를 바탕으로 학교생활 전반, 교우 관계, 학업 태도, 장점 또는 발전 가능성이 드러나도록 총 네 문장으로 구성한다. 모든 선택 키워드를 억지로 한 번씩 나열하지 않고 자연스럽게 묶되, 어떤 키워드가 어느 문장에 반영되었는지 검토 화면에서 확인할 수 있게 한다.

키워드는 관찰 사실을 증명하는 자료가 아니므로 Gemini는 입력에 없는 사건, 역할, 수치, 성취, 변화 과정이나 구체적인 행동 사례를 만들어내지 않는다. 부정적이거나 개선이 필요한 사용자 정의 키워드는 낙인이나 과장 없이 중립적인 언어로 바꾸고 발전 가능성을 중심으로 표현한다. ‘스스로 고치려고 노력함’처럼 확인되지 않은 변화나 노력을 임의로 추가하지 않는다.

<기능3> 창의적 체험활동 자율활동 문장을 출력하는 기능

자율활동 주제를 문서로 받은 경우 기능 1과 같은 서버 측 파일 처리 흐름을 사용하여 Gemini가 활동 주제를 추출한다. 친구사랑주간, 학교폭력예방교육, 다문화이해교육, 소방훈련과 같은 주제를 사용자가 직접 입력할 수도 있다.

사용자가 입력하거나 문서에서 추출한 활동 주제가 네 개 미만이면 문장 생성을 시작할 수 없으며, 주제를 네 개 이상 입력하도록 안내한다. 사용자는 생성할 학생 수를 입력한다. 프로그램은 ‘학생 1’부터 각 순번에 서로 다른 활동 주제 네 개를 무작위로 배정하고 생성 전에 배정 결과를 보여준다. 한 학생 순번에는 같은 주제를 중복 배정하지 않지만 서로 다른 순번에는 같은 주제를 배정할 수 있다.

사용자는 각 학생 순번의 주제 네 개를 검토하여 직접 변경하거나 다시 무작위 배정할 수 있다. 사용자가 배정 결과를 승인한 후에만 생성 단계로 넘어간다.

사용자는 한 문장당 목표 글자 수를 입력한다. 모든 학생 순번에 동일하게 일반적이고 긍정적인 참여 수준을 적용한다. Gemini는 승인된 주제 네 개에 대해 주제당 한 문장씩 총 네 문장을 생성하고 하나의 문단으로 연결한다. 입력하거나 승인하지 않은 활동과 구체적인 사건을 추가하지 않는다.

<문장 생성과 검수>

Gemini 3.5 Flash Lite는 기능 1의 구조화된 성취기준·평가요소·고정된 ‘상’ 기준, 기능 2의 선택 키워드와 기능 3의 활동 주제를 바탕으로 여러 문장을 생성한다. 단어만 바꾸는 변형이 아니라 문장 구조와 강조점이 실질적으로 다른 문장을 만들되, 입력에 없는 활동이나 사실을 임의로 추가하지 않는다.

모델 응답은 서버에서 정의한 구조화된 스키마로만 받고, 스키마 검증을 통과한 본문만 브라우저에 반환한다. 프롬프트, 모델명, Google 요청 형식과 외부 API 주소는 서버 내부에 둔다. 클라이언트가 임의의 시스템 프롬프트, 모델명 또는 외부 요청 주소를 지정할 수 없게 한다.

공통 작성 옵션, 사용자 정의 키워드와 문서에서 추출한 텍스트는 모두 신뢰할 수 없는 사용자 데이터로 취급한다. 서버는 각 입력의 길이, 허용 문자와 배열 개수를 제한하고, 이 내용을 시스템 지시문과 분리된 데이터 필드로만 모델에 전달한다. 사용자 입력이 모델 선택, 출력 스키마, 보안 규칙과 시스템 지시를 덮어쓰지 못하게 한다.

생성된 각 문장은 별도 검수 단계를 거친다. Gemini는 입력 근거 부합 여부, 입력에 없는 사실 추가 여부, 과장·단정·부정적 낙인·차별적 표현 여부를 검수한다. 서버는 명사형 종결, 마침표 종결, 금지 표현, 문장 개수, 공백·줄바꿈·문장부호를 제외한 글자 수, 영어 알파벳 포함 여부, 번호·불릿·마크다운·불필요한 기호 사용 여부를 규칙으로 직접 검사한다. 문제가 있으면 이유를 보여주고 문제가 있는 문장만 재생성한다.

중복 검사는 완전히 동일한 문장, 같은 단어나 문장 구조가 반복되는 표현 중복과 다른 단어로 같은 내용을 말하는 의미 중복을 포함한다. 완전히 동일한 문장은 허용하지 않고 즉시 재생성한다. 문자열·표현 비교 결과와 Gemini의 의미 유사도 판정을 함께 사용하여 100점 기준 유사도 점수와 겹치는 부분을 보여준다.

유사도가 85점 이상이면 전체 결과가 아니라 중복으로 판정된 해당 문장만 재생성한다. 재생성한 문장은 이미 통과한 전체 문장과 다시 비교한다. 문장별로 최대 세 번까지 재생성하며, 세 번 후에도 중복이면 자동 확정하지 않고 교사가 직접 수정하거나 사용 여부를 판단하게 한다. 한 학생 순번의 여러 문장 사이와 전체 학생 순번 사이를 모두 비교한다.

<근거 표시와 교사 확정>

기능 1은 반영된 성취기준, 평가요소와 자동 적용된 ‘상’ 기준을 보여주되 사용자 선택값처럼 표시하지 않는다. 기능 2는 반영된 기본 키워드와 사용자 정의 키워드를 보여준다. 관찰 날짜, 관찰 기록과 추론 표시는 사용하지 않는다. 기능 3은 반영된 활동 주제와 승인한 배정 결과를 보여준다.

교사는 생성 결과와 검수 결과를 확인하고 특정 단어나 문장을 직접 수정하거나 선택한 문장만 재생성할 수 있다. 자동 생성 결과는 교사가 최종 확정해야 완성된다. 직접 수정한 문장에도 글자 수와 형식 검사를 다시 적용한다.

<배치 작업과 브라우저 저장 이력>

학생 순번 전체의 문장을 한 번에 생성하는 배치 작업을 지원한다. 생성, 형식 규칙 검사, 의미 중복 검사와 최종 수정 단계를 구분하여 진행 상태와 실패 이유를 항목별로 보여준다. 일부 교과, 학생 순번 또는 문장의 생성이 실패해도 나머지 작업은 계속 진행하고, 실패한 항목만 모아 재시도할 수 있게 한다.

긴 배치는 Vercel 함수의 실행 시간 제한을 피하도록 교과 또는 일정 개수의 학생 순번 단위로 나누어 요청한다. 브라우저는 각 요청의 완료 상태를 기록하고, 전송 중인 작업의 생성 버튼을 비활성화하여 같은 요청의 동시 제출을 막는다. 완료되지 않은 묶음만 제한된 횟수로 다시 요청하고 모든 요청에 작업 식별자를 포함하여 진행 상태와 오류를 연결한다.

서버 데이터베이스를 사용하지 않으므로 네트워크가 응답 전에 끊겼을 때 Gemini 호출이 이미 완료되었는지를 다음 서버리스 요청에서 확실히 판별할 수 없다. 따라서 정확히 한 번 실행되는 멱등성을 보장한다고 표현하지 않는다. 재시도 전에 기존 응답 수신 여부를 브라우저에서 확인하고, 처리 결과가 불명확한 요청은 새 결과와 추가 API 비용이 발생할 수 있음을 안내한다. 향후 강한 멱등성이 필요하면 만료 시간이 짧은 서버 측 작업 저장소를 별도 도입한다.

교사가 선택하거나 수정한 문장, 재생성 이유, 검수 결과와 최종 확정 상태는 localStorage에 저장한다. 현재 작업과 최근 버전만 제한적으로 보관하여 동기식 저장이 화면 반응을 방해하거나 저장 용량을 초과하지 않게 한다. 자주 바뀌는 입력은 짧은 지연 후 한 번에 저장하고, 생성 완료와 최종 확정처럼 중요한 시점에는 즉시 저장한다. 브라우저를 다시 열면 최근 작업을 복구할 수 있게 하고, 사용자가 현재 초안만 버리거나 전체 이력을 삭제할 수 있게 한다. 브라우저 저장 데이터는 서버 계정과 동기화하지 않는다.

<XLSX 출력과 클립보드 복사>

최종 확정된 결과는 XLSX로 내려받을 수 있다. 통합 XLSX에서 기능 1 결과는 ‘기능1_국어’, ‘기능1_수학’과 같이 교과별 시트로 나누고, 기능 2와 기능 3도 각각 별도 시트로 저장한다. 통합 파일 외에 선택한 교과 또는 기능의 결과만 담은 개별 XLSX도 제공한다.

학생 명단을 관리하지 않으므로 XLSX에는 학생 이름이나 학번 대신 학생 순번을 기록한다. 각 시트에는 학생 순번, 최종 문단, 최종 확정 여부와 기능별 근거를 저장한다. 기능 1은 교과명, 성취기준, 평가요소와 자동 적용된 ‘상’ 기준, 기능 2는 선택한 기본·사용자 정의 키워드, 기능 3은 승인한 활동 주제를 근거로 저장한다. 기능 1에는 사용자 수준 선택 열을 만들지 않는다.

웹브라우저는 보안상 다른 사이트의 입력칸을 찾아 전역 단축키와 키보드 입력으로 자동 붙여넣는 기능을 안정적으로 제공할 수 없다. 따라서 나이스 자동 입력, 전역 단축키, 자동 탭 이동, 붙여넣기 대기열과 자동 일시정지 기능은 삭제한다.

대신 HTTPS에서 제공되는 브라우저 Clipboard API를 사용하여 사용자가 명시적으로 버튼을 누를 때만 복사한다. 개별 문단 복사와 현재 교과·기능의 전체 결과 복사를 제공하고, 전체 복사는 학생 순번대로 줄바꿈하거나 표 형식으로 복사할 수 있게 한다. 클립보드 권한이 없거나 복사에 실패하면 결과를 선택 가능한 텍스트 영역에 표시하여 사용자가 직접 복사할 수 있게 한다. 나이스 입력은 사용자가 복사한 내용을 직접 붙여넣고 최종 확인하는 방식으로 한다.

<Gemini API와 배포 보안>

Production 배포에는 서로 다른 Google 계정이 소유한 서로 다른 Google Cloud 프로젝트 세 곳에서 Gemini API 키를 하나씩 발급하여 사용한다. Vercel 환경 변수 이름은 프로젝트 우선순서에 따라 GEMINI_API_KEY_1, GEMINI_API_KEY_2, GEMINI_API_KEY_3으로 고정하고 NEXT_PUBLIC_ 접두사를 사용하지 않는다. 운영 목표는 세 키를 모두 구성하는 것이지만, 키 교체나 장애 중에도 정상 키로 서비스를 유지할 수 있도록 애플리케이션 실행 조건은 GEMINI_API_KEY_1 필수, 두 번째와 세 번째 키 선택으로 둔다. 실제 API 모델 식별자는 GEMINI_MODEL 환경 변수로 관리하며 배포 값은 Gemini 3.5 Flash Lite의 유효한 모델 식별자로 지정한다. 환경 변수는 사용자가 아닌 배포 운영자가 관리하고, API 키 입력·저장·조회·삭제와 모델 선택 UI는 만들지 않는다.

서버는 시작 또는 첫 요청 시 세 키를 숫자 순서로 읽고 비어 있는 선택 키와 같은 값이 중복된 키를 제외하여 최대 세 개의 키 풀을 만든다. 키 값은 애플리케이션 상태, localStorage, 응답과 로그에 복사하지 않고 Gemini 클라이언트를 생성하는 서버 전용 메모리에서만 사용한다. 첫 번째 키가 없거나 모델 환경 변수가 없으면 설정 오류로 처리하고, 두 번째 또는 세 번째 키만 잘못 설정된 경우에는 정상 키로 서비스를 계속 제공하면서 비밀값이 없는 운영 경고를 남긴다.

<Gemini API 키 장애조치>

각 Gemini 작업은 기본적으로 키 1부터 시작한다. 키 1이 장애조치 대상 오류로 실패하면 같은 요청 데이터와 모델 설정을 사용하여 키 2로 다시 호출하고, 키 2도 같은 종류의 오류로 실패하면 키 3으로 한 번 더 호출한다. 구성된 마지막 키까지 실패하면 추가 순환 없이 해당 작업을 실패로 종료한다. 브라우저에는 어느 키를 사용했는지, 구성된 키 개수와 키별 오류를 알리지 않고 일반화된 재시도 안내만 반환한다.

장애조치 대상은 키가 누락·폐기·차단되었거나 해당 프로젝트 권한이 없는 경우에 해당하는 인증·권한 오류와, 요청·토큰·일일·지출 할당량 초과를 뜻하는 429 RESOURCE_EXHAUSTED로 제한한다. 429가 짧은 시간의 속도 제한으로 판단되고 Vercel 함수의 남은 실행 시간이 충분하면 Retry-After를 우선 존중하거나 지수 백오프와 무작위 지연을 한 차례 적용한 뒤 같은 키를 다시 시도할 수 있다. 그래도 실패하면 다음 키로 전환한다.

잘못된 입력이나 요청 형식에 따른 400, 존재하지 않는 모델·리소스에 따른 404, 콘텐츠 안전 정책 거부처럼 키를 바꿔도 해결되지 않는 오류에는 다음 키를 사용하지 않는다. Google 측의 5xx 또는 503은 제공자 장애일 가능성이 높으므로 제한된 지수 백오프만 적용하고 키 순환으로 동일 요청을 확산하지 않는다. 응답을 받기 전 네트워크 타임아웃이나 연결 종료가 발생하면 모델이 이미 결과를 생성했을 수 있으므로 즉시 다른 키로 재호출하지 않고 처리 결과가 불명확함을 안내한다.

Gemini의 요청 한도는 API 키가 아니라 키가 연결된 Google Cloud 프로젝트 단위로 적용된다. 이 서비스의 세 키는 서로 다른 Google 계정의 별도 프로젝트에 연결하므로 프로젝트 1의 할당량이 소진되어 429가 발생해도 프로젝트 2 또는 프로젝트 3의 남은 할당량으로 작업을 이어갈 수 있다. 다만 프로젝트별 한도와 계정 상태가 각각 정상이어야 하며, Google 전체 서비스 장애나 모델 용량 부족은 프로젝트를 바꾸어도 해결되지 않을 수 있다.

세 Google 계정과 프로젝트는 모두 서비스 운영자가 정당하게 소유하거나 관리 권한을 가진 범위에서 운영하고, 각 프로젝트의 결제 상태, Gemini API 사용 가능 여부, 할당량과 정책 준수 여부를 별도로 관리한다. 장애조치는 서비스 연속성을 위한 장치이며 제공자의 이용 정책을 회피하는 방식으로 운영하지 않는다. 프로젝트별 비용과 한도를 함께 모니터링하고 세 프로젝트의 합산 호출량에도 애플리케이션 자체 사용량 상한을 적용한다.

서버 데이터베이스나 공유 키 상태 저장소를 사용하지 않으므로 장애조치 상태는 현재 요청 안에서만 유효하다. 한 Vercel 인스턴스의 메모리에 짧은 키 냉각 시간을 둘 수는 있지만 다른 인스턴스와 공유되지 않으므로 전역 상태로 신뢰하지 않는다. 새 요청은 다시 키 1부터 검증할 수 있다. 여러 요청에 걸쳐 소진된 키를 건너뛰어야 한다면 향후 만료 시간이 있는 공유 상태 저장소를 별도로 도입한다.

로컬 개발에서는 버전 관리에서 제외한 .env.local에 개발에 사용할 키 하나와 GEMINI_MODEL만 저장하고, 장애조치 테스트가 필요할 때만 나머지 두 키를 임시로 추가한다. 저장소의 .env.example에는 네 환경 변수 이름, 필수·선택 여부와 설명만 두고 실제 키나 Google 계정 정보를 포함하지 않는다. Production에는 세 키를 모두 주입하고, Preview와 Development에는 꼭 필요한 키만 환경 범위를 제한하여 주입한다. 동일한 세 운영 키를 Preview와 로컬 부하 테스트에 상시 사용하여 운영 할당량을 예상치 못하게 소모하지 않는다. 키 교체와 폐기는 각 Google 계정의 API 키 관리 화면과 Vercel 관리 화면에서 수행하고 필요한 환경에 다시 배포한다.

Google Gemini SDK와 API 호출 모듈은 server-only로 표시한 서버 코드에서만 가져오고, 환경 변수도 해당 모듈에서만 읽는다. 프론트엔드는 Vercel의 같은 출처 Route Handler에만 POST 요청을 보내며, 요청 본문에 API 키, 모델명 또는 외부 API 주소를 포함하지 않는다. 응답에는 생성 결과와 필요한 검수 정보만 포함한다. 서버 오류 메시지에도 API 키, Google 요청 주소, 원본 SDK 오류 객체, 프롬프트와 내부 스택을 노출하지 않는다.

서버는 필수 환경 변수와 키 풀을 검증하고 사용 가능한 키가 하나도 없으면 Gemini SDK를 호출하지 않고 일반화된 서비스 설정 오류와 비밀값이 없는 진단 코드를 반환한다. API 키의 일부 값, 해시와 식별 가능한 접두사도 브라우저 응답이나 로그에 출력하지 않으며, 클라이언트에서 환경 변수 누락을 보완하는 흐름은 두지 않는다. 운영 로그와 지표에는 key-1, key-2, key-3과 같은 슬롯 번호, 정규화한 오류 종류, 전환 여부와 소요 시간만 남긴다. 생성·검수 API 응답에는 Cache-Control: no-store를 적용하여 개인 작업 내용이 공유 캐시나 CDN 캐시에 남지 않게 한다.

브라우저에서 내부 서버 요청 주소가 보이는 것은 정상이며 이를 보안 수단으로 숨기거나 난독화하지 않는다. 보안은 비밀 키와 외부 호출을 서버에 격리하고, 요청 인증, 허용 Origin 검사, CSRF 방어, 요청당 파일 크기와 학생 수 제한, 속도 제한과 사용량 제한을 적용하는 방식으로 확보한다. 공개 배포 시 무단 API 사용과 비용 발생을 막기 위해 최소한의 로그인 또는 Vercel 배포 접근 제한을 적용한다.

업로드 파일은 확장자만 믿지 않고 실제 MIME 형식과 파일 크기를 서버에서 검사한다. 지원하지 않는 파일, 암호화되거나 손상된 문서와 제한을 초과한 요청은 Gemini에 보내기 전에 거부한다. 프롬프트 인젝션을 줄이기 위해 업로드 문서의 내용은 명령이 아니라 추출 대상 데이터로만 취급하고, 허용된 스키마의 필드만 결과로 받는다.

생성 문장, 사용자 정의 키워드와 업로드 문서에서 추출한 문자열은 HTML로 삽입하지 않고 React의 일반 텍스트 렌더링과 입력값으로만 표시한다. dangerouslySetInnerHTML 같은 원시 HTML 삽입을 사용하지 않고, 엄격한 Content Security Policy와 보안 응답 헤더를 적용한다. localStorage는 페이지의 JavaScript가 접근할 수 있으므로 XSS 방지가 저장 결과 보호의 필수 조건이다.

서버 로그와 분석 도구에는 API 키, 업로드 문서 내용, 선택 키워드, 생성 문장과 전체 모델 요청·응답을 남기지 않는다. 오류 추적에는 비식별 작업 ID, 처리 단계, 상태 코드와 소요 시간처럼 운영에 필요한 최소 정보만 기록한다.

<API 비용과 운영>

배포 전과 정기적으로 Gemini 3.5 Flash Lite의 최신 모델 식별자, 요금, 요청 한도, 파일 지원 범위와 데이터 처리 정책을 확인한다. 모델 식별자 변경은 GEMINI_MODEL 환경 변수와 재배포로 처리하며 사용자가 화면에서 변경할 수 없게 한다. 배포 후에는 학생 식별 정보가 없는 점검 요청으로 환경 변수와 모델 연결 상태를 확인한다.

요청 전에 예상 생성 문장 수를 보여주고 사용자의 확인을 받는다. 중복 검수와 재생성 횟수에 상한을 두며, 서버에서 사용자별 또는 배포별 사용량 제한을 적용하여 예기치 않은 비용 증가를 막는다. Gemini 요청 실패 시 비밀 정보가 없는 사용자용 오류 메시지와 재시도 방법을 제공한다.

장애조치는 성공할 때까지 무제한 순환하지 않고 작업당 구성된 키를 순서대로 최대 한 차례씩 사용하는 것을 기본으로 한다. 짧은 429 백오프 재시도를 허용하더라도 키별 추가 시도는 한 차례로 제한한다. 키 슬롯별 요청 수, 성공률, 429·인증·권한 오류 수와 장애조치 성공률을 비밀값 없이 집계하여 불필요한 중복 호출과 비용 증가를 확인한다.

<품질 평가>

시스템의 품질은 평가기준과 기능 1의 고정된 ‘상’ 기준 부합도, 선택 키워드·활동 주제 충실도, 할루시네이션 여부, 금지 표현 위반, 명사형 종결과 글자 수 준수, 학생 순번 간 중복도와 교사의 최종 수정량으로 평가한다. 가명이나 순번만 사용한 예시 데이터로 반복 실행하여 결과의 안정성을 확인하고 프롬프트와 검수 규칙을 조정한다.

기능 2는 관찰 기록이 아니라 키워드만 사용한다는 한계를 별도로 평가한다. 선택 키워드에서 확인할 수 없는 구체적인 행동이나 성취를 만들어내지 않는지, 키워드를 부자연스럽게 나열하지 않는지, 서로 다른 키워드 조합이 충분히 구별되는 결과를 만드는지를 집중적으로 검사한다.

<기술 스택>

앱의 전체 요청 흐름은 ‘브라우저 화면 → 같은 출처의 Next.js 서버 API → Vercel 서버 함수 → Google Gemini API → 서버 검수 → 브라우저 결과 표시 및 localStorage 저장’으로 구성한다. 브라우저는 Google Gemini API를 직접 호출하지 않고 서버가 검증하여 반환한 최종 데이터만 받는다.

프론트엔드는 Next.js App Router, TypeScript와 React로 개발한다. 주요 내비게이션에는 기능 1, 기능 2, 기능 3만 두고 설정 탭은 만들지 않는다. 입력 폼, 학생 순번별 표, 키워드 복수 선택, 공통 작성 옵션, 생성 진행 상태, 결과 편집과 검수 화면을 React 컴포넌트로 구성한다. 브라우저 데이터 삭제와 내보내기는 헤더 메뉴로 분리한다. 서버에서 처음 렌더링해도 되는 화면과 localStorage·Clipboard API를 사용하는 클라이언트 컴포넌트를 분리한다. 입력값과 화면 상태의 스키마 검증에는 Zod를 공통으로 사용하고, 서버와 클라이언트가 같은 타입 정의를 공유한다.

클라이언트 저장소는 Web Storage API의 localStorage를 사용한다. 기능별 작업 상태와 생성 결과를 JSON으로 직렬화하고 데이터 버전, 최근 수정 시각과 작업 식별자를 함께 저장한다. localStorage 접근은 브라우저 마운트 이후에만 실행하며, 저장과 파싱은 예외 처리한다. 용량 초과, 손상된 JSON, 이전 스키마와의 불일치, 사이트 데이터 삭제와 공용 PC 사용 상황을 처리하는 복원·초기화·내보내기 UI를 제공한다. 업로드 파일과 비밀값은 localStorage에 저장하지 않는다.

서버 API는 Next.js Route Handler를 기본으로 사용하고 Vercel Functions에서 실행한다. 문장 생성, 문장 재생성, 의미 검수, 평가계획서·활동 문서 분석처럼 Gemini가 필요한 작업은 모두 POST 기반 서버 엔드포인트에서 처리한다. 단순 UI 변경이나 localStorage 저장에는 서버 요청을 사용하지 않는다. 파일 업로드처럼 요청 본문과 응답 상태를 세밀하게 제어해야 하는 작업도 전용 Route Handler로 분리한다.

Google Gemini SDK는 server-only 모듈에서만 불러온다. 서버 전용 환경 설정 모듈은 GEMINI_API_KEY_1, GEMINI_API_KEY_2, GEMINI_API_KEY_3과 GEMINI_MODEL을 읽어 검증된 키 풀을 만든다. 공통 GeminiFailoverClient는 키 1→2→3 전환, 오류 정규화, 제한된 백오프와 비밀값 없는 관측 정보를 담당하고, 문장 생성·재생성·검수·문서 분석 서비스가 모두 이 클라이언트를 사용한다.

서버 API는 필수 환경 변수와 키 풀을 확인한 뒤 클라이언트 입력을 Zod로 검증하고, 서버가 보유한 시스템 프롬프트와 모델 설정으로 Gemini 3.5 Flash Lite를 호출한다. 클라이언트 요청에는 키, 모델명, 키 슬롯과 외부 API 주소를 넣지 않는다. 모델 응답도 구조화된 스키마로 검증한 뒤 글자 수, 종결 형식, 금지 표현과 중복 규칙을 서버에서 검사하여 필요한 결과만 Cache-Control: no-store 응답으로 반환한다.

문서 처리는 Vercel 서버에서 수행한다. PDF와 이미지는 파일 형식·MIME·용량을 확인한 뒤 Gemini의 문서·이미지 입력으로 전달하고, DOCX, PPTX와 XLSX는 Node.js 서버용 파서로 텍스트와 표 구조를 추출한 뒤 Gemini에 전달한다. HWP와 HWPX는 지원하지 않고 PDF 변환을 안내한다. 임시 파일이 필요하면 요청 중에만 사용하고 처리 완료 후 영구 저장하지 않는다.

XLSX 다운로드는 ExcelJS 또는 SheetJS와 같은 웹 호환 라이브러리로 생성한다. 생성 결과만으로 만들 수 있는 XLSX는 브라우저에서 생성하여 불필요한 서버 전송을 줄이고, 서버 처리 결과가 필요한 경우에도 학생 식별 정보를 추가하지 않는다. 클립보드 복사는 Vercel의 HTTPS 환경에서 navigator.clipboard API로 구현하고 사용자의 버튼 클릭이 있을 때만 실행한다.

배포는 GitHub의 기존 `evaluator` 저장소와 Vercel Git 연동을 사용한다. GitHub CLI로 원격 저장소와 Pull Request를 관리하고 Vercel CLI로 로컬 프로젝트를 연결한 뒤 `vercel git connect`로 그 원격 저장소를 배포 소스에 연결한다. 기능 브랜치와 Pull Request는 Preview, `main` 병합은 Production을 자동 배포하며 CLI로 배포 상태·로그·점검 결과를 확인한다. Production의 키 슬롯 1·2·3에는 서로 다른 Google 계정의 독립된 Google Cloud 프로젝트 키를 하나씩 연결한다. Production, Preview, Development의 환경 변수 범위를 분리하고 .env.local, 실제 키, 계정 이메일, 프로젝트 식별자와 결제 정보는 버전 관리에서 제외한다. 키 슬롯과 프로젝트의 대응 관계는 비밀값을 적지 않은 별도 운영 문서에서 관리하고, 각 프로젝트의 할당량·비용·키 상태를 개별 확인한다. 공개 배포에는 인증 또는 Vercel 접근 제한, 허용 Origin 검사, CSRF 방어, 요청 크기 제한, 속도 제한, 세 프로젝트 합산 사용량 제한, Content Security Policy와 오류 정보 정제를 적용한다. 서버 로그에는 프롬프트, 업로드 문서, 선택 키워드, 생성 문장과 Gemini 원문 응답을 기록하지 않는다.

단위·컴포넌트 테스트에는 Vitest와 React Testing Library를 사용하고, 실제 브라우저 흐름에는 Playwright를 사용한다. 문장 규칙, 글자 수 계산, 중복 검사, 입력·모델 응답 스키마, 파일 검증, 서버 API 오류 처리, localStorage 저장·복원·삭제·스키마 마이그레이션·용량 초과, XLSX 출력과 클립보드 실패 대체 흐름을 각각 검사한다.

키 장애조치 테스트는 서로 다른 프로젝트를 나타내는 모의 키 슬롯을 사용한다. 키 1 성공 시 추가 호출이 없는지, 키 1 프로젝트의 인증·권한 오류 또는 429 후 키 2와 키 3을 순서대로 사용하는지, 성공한 즉시 순환을 멈추는지, 최대 세 키를 넘지 않는지와 중복·빈 키를 제외하는지를 검증한다. 400·404·콘텐츠 거부·5xx·불명확한 타임아웃에는 정해진 규칙 밖의 키 전환이 없는지, 모든 키가 실패하면 일반화된 오류만 반환하는지도 확인한다. 실제 세 키를 사용하는 배포 후 점검은 학생 데이터가 없는 최소 요청으로 각 슬롯을 개별 확인하고 부하 테스트로 운영 할당량을 소모하지 않는다.

설정 탭과 API 키 입력 UI가 존재하지 않는지, 환경 변수 누락 시 생성이 안전하게 중단되는지, 클라이언트 요청에 키·모델명·키 슬롯·외부 주소가 포함되지 않는지, API 응답이 캐시되지 않는지도 확인한다. 배포 빌드의 클라이언트 번들과 소스맵에 GEMINI_API_KEY_1, GEMINI_API_KEY_2, GEMINI_API_KEY_3의 값, Google API 주소, 시스템 프롬프트와 Gemini SDK 서버 코드가 포함되지 않았는지도 검사한다.
